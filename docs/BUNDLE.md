# GastroSuit — Reading the Design Handoff

Status: agreed · 2026-11-07

## 0. The rule

The handoff defines **what the app looks like and how it behaves**. It does not define the
architecture or how screens are split into widgets — that is decided in this project, from
scratch, per screen.

The handoff was generated by Claude Design and checked by the designer as rendered pages.
Its components are how the tool drew the design, not a widget specification. A widget may
end up matching a handoff component one to one, or be split differently; either is decided
on its own merits.

---

## 1. What to read

Location: `coffee-house-ui/project/`. Only the files that render the pages in a browser
are read; they are what the designer checked.

| What | Where | Read for |
|---|---|---|
| Screens | `*.dc.html` | Layout of a screen, spacing, order of blocks, states, behaviour |
| Nested screens | `<dc-import name="…">` in a page → `<name>.dc.html` | Overlays and bottom sheets opened from a screen |
| Pieces of a screen | `_ds/gastro-design-system-*/_ds_bundle.js`, used by a page through `<x-import component-from-global-scope="…">` | How a piece looks in detail: sizes, spacing, states |
| Tokens | `_ds/gastro-design-system-*/tokens/*.css` | Already mapped into code, see `DESIGN_SYSTEM.md` |
| Grid | `LAYOUT_RULES.md` | Side margins, gutters, columns in the 360px frame |
| Icons | Phosphor (regular and fill), loaded by the pages from a CDN | Icon names and which weight shows when |
| Images | `uploads/` | Examples only; real images come from the API |

The 360px frame is the reference width. The app adapts to the device's screen size
(`DESIGN_SYSTEM.md` §6).

---

## 2. What to take and what not

Take:
- Look: sizes, spacing, colours, typography, radii, shadows — always through the design
  system tokens.
- Layout: what sits where on a screen, what scrolls, what sticks.
- Behaviour: what is tappable, what opens what, which states exist (empty, selected,
  added, loading as drawn).

Do not take:
- How a screen is split into components, component names, props, internal structure.
- The handoff's component list as a work plan.
- Page logic: `setState`, `{{ }}` bindings, `sc-if` / `sc-for`, scripts. They show what
  state a screen has, never how to manage it; state follows `ARCHITECTURE_SPEC.md` §6.
- Web markup, class names, inline styles as code.

---

## 3. What is not read

- Variants of pages: `*-print.dc.html`, `*-standalone.dc.html`, `Home Alt.dc.html`,
  `Splash v1.dc.html`, `Column Layout.dc.html`, `Home Screen.html`, `Order Screen.html`.
- JSON exports: `components/*.json`, `screens/*.json`, `Home.screen.json`.
- Older snapshots: `design_handoff_home_order/`, `export/`, `handover/`, `screenshots/`.
- `support.js` — the design tool's template runtime.

If a page and one of these disagree, the page wins.
